# Security policy

QARAWORK is a collection of early-stage prototypes. Do not assume suitability for production or regulated use without independent risk assessment, validation, and appropriate security controls.

## Reporting vulnerabilities

Please do not publish credentials, exploit details, or sensitive reports in public GitHub issues.

Please use GitHub's private vulnerability reporting feature, if enabled for this repository. Otherwise, contact the repository maintainer privately through a channel listed on their GitHub profile. Do not disclose security details in public issues.

## Credential handling

Use least-privilege credentials and limit each integration to authorized resources. Do not store tokens in code, samples, logs, issues, or version-controlled MCP-client configuration.

## Data handling

Test with synthetic records. Do not include patient data or confidential medical-device documentation in public issues, examples, or demonstration workspaces.

## Supported status

A public release must explicitly identify supported versions and maintenance expectations. No production security guarantees are implied by a prototype designation.
